The case, end to end

One assistance case from the hospital desk to a finished case. Server actions are named where the step runs in a Cloud Function.

flowchart TD
  A([Patient visits the hospital office]) --> B[Staff issue an access code<br/>issueAccessCode]
  B --> C[Patient registers or signs in<br/>claims the code · claimAccessCode]
  C --> D[Files a request<br/>bill · documents · live selfie · declaration]
  D --> E{Hospital verifies documents}
  E -- returned --> D
  E -- all verified --> F[Remote assessment<br/>case conversation · intake sheet]
  F --> G{Endorse gate on the server<br/>endorseRequest}
  G -- blocked --> F
  G -- passes --> H[Slices created, one per agency<br/>slots taken]
  H --> I{Patient accepts the plan<br/>Proceed}
  I -- not in 3 days --> X1[Slice closes · caseTimers]
  I -- accepts --> J[Agency reviews<br/>decideSlice]
  J -- needs info --> K[Patient answers] --> J
  J -- rejects --> L[Slice rejected]
  J -- approves --> M[Guarantee Letter issued<br/>10-day validity]
  M --> N{Letter settles<br/>settleLetter · glExpirySweep}
  N -- redeemed --> O[Billed amount disbursed]
  N -- expired --> P[Budget released]
  L --> Q{Anything still pending?}
  X1 --> Q
  O --> R{Fully funded and every letter settled?}
  P --> R
  R -- yes --> Z([Case finished · patient may file again])
  R -- no --> Q
  Q -- no --> S[Endorse more or close<br/>auto-closes after 7 days]
  S -- endorse more --> G
  S -- close --> Z
  D -. patient withdraws early .-> Z

Roles: the patient files and accepts; the hospital (gateway) verifies, assesses and endorses; each agency decides its own slice and issues the Guarantee Letter; the Super Admin runs the network (hospitals, agencies, onboarding) and never sees patient data.

The shared shell

Every signed-in screen sits inside the shell (components/Layout.jsx): role-specific sidebar or bottom bar, the notifications bell, the messages drawer, the profile menu, the announcement banner, the offline banner and the install nudge. Staff pass MfaGate first.

How this was made

The routes, page parts, dialogs, server actions, collections, links between screens and the functions list were read from the code (src/App.jsx, every file under src/pages and src/components, functions/index.js, functions/src and firestore.rules) at 8a91901. The descriptions were written by hand against that inventory. Dialog names are their titles where the title is fixed text, otherwise the dialog’s component name. Data columns show what each screen touches directly or through its components; helper modules under src/utils count one step deep.
